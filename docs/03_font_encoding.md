# Шрифт PS2 и кодировка кириллицы (этап 3)

## Где шрифт

- Файл `383c45.raw` (47 472 Б), регион `resident`, внутри `STAGE.DAT`.
- Лежит в **5 уровнях**: `init`, `net`, `r_sna01`, `r_sna02`, `r_sna03` — патчить все копии.
- Секция сжата zlib и зашифрована (XOR-LCG) — для вставки нужна обратная упаковка
  (`tools/stagedat.py` пока только распаковывает).
- В `SLOT.DAT` и других уровнях шрифтов нет.

## Формат

```
u16 base        = 904 — начало данных глифов (конец таблицы)
u16 0x0800
u32 data_end    = 19528
u32 ?
223 × { u16 offset (от base), u16 info }   — коды 0x21..0xFF
    info: биты 4..10 = ширина-1 (px), 0x800 = «хвост» вниз (g j p q y ( ) [ ] …)
глифы: высота 24, 2 бита/пиксель (4 оттенка), строки упакованы побитно, старшие биты первыми
код 0x20 (пробел) — глиф по смещению 0
после 19528: японская кана + значки кнопок ○ △ □ × (24×24, 2bpp)
```

Превью: `work/font_sheet.png` (основной шрифт), `work/font_extra.png` (кана и значки).

**Важно:** шрифт уже содержит 0x80–0xFF — это раскладка **Mac Roman** (Ä Å Ç É … ). Расширять
таблицу не нужно: кириллицу рисуем поверх неиспользуемых глифов.

## Выбранная кодировка — Windows-1251

| Коды | Что там будет |
|---|---|
| 0x20–0x7E | ASCII, как в оригинале |
| 0x80 | **занят**: префикс переноса строки (`0x80 0x7C`) |
| 0xC0–0xFF | А–Я, а–я |
| 0xA8 / 0xB8 | Ё / ё |
| 0x85 0x96 0x97 0xAB 0xBB 0xB9 | … – — « » № |
| остальные | старые глифы Mac Roman (© ™ ° и т. п. остаются) |

Почему так:
- Русский текст кодека и меню в ПК-русификаторе **уже записан в cp1251** — его байты можно брать как есть.
- Стандартная кодировка: конвертация в одну строку (`tools/encoding_ru.py`).
- Все 5990 строк субтитров кодируются без потерь (проверено).

Чем жертвуем: глифы Mac Roman на этих позициях (À Ã Õ Œ œ – — “ ” ‘ ’ … ® π ª и др.). В английском
тексте субтитров они не встречаются; если всплывут в меню/кодеке — заменим текстом.

Буквы с хвостом вниз (флаг 0x800): Д Ц Щ д ц щ р у ф.

## Что ещё не подтверждено → тест в эмуляторе

Сразу за шрифтом лежит японская кана, значит, движок понимает и **двухбайтовые коды**. Нужно
убедиться, что байты 0x81–0xFF выводятся как одиночные символы, а не как служебные/двухбайтовые.

**Тестовый образ:** `work/iso/MGS3_charset_test.iso`. В первой катсцене (брифинг Майора Зеро
в самолёте, «Listen up, Jack.») вместо первых 5 субтитров выводятся коды:

```
81:<81..8F>
90:<90..9F> / A0:<A0..AF>
B0:<B0..BF> / C0:<C0..CF>
D0:<D0..DF> / E0:<E0..EF>
F0:<F0..FF>
```

Ожидаемый результат — ровно символы из `work/font_sheet.png` в тех же позициях
(81 → Å, 82 → Ç, … C0 → ¿ …). Если что-то пропадёт, «съест» следующий байт или сломает строку —
такие коды под кириллицу использовать нельзя.

## Результат теста в PCSX2 (24.10.2026)

Тест в сцене в самолёте (`v020_010`, PS2 id 1900–1908; первая попытка ошибочно была в
`v020_030`, до которой не дошли). Скриншоты: `PCSX2/snaps/`, сводка: `work/charset_test_subs.png`.

**Байты 0x81–0xFF НЕ выводятся как одиночные символы Mac Roman.** Игра читает байт ≥0x80
как начало двухбайтового кода:

- `81 82` → «パ» = глиф №129 доп. блока (кана), т. е. индекс = 2-й байт − 1 при ведущем 0x81;
- остальные пары (`83 84`, `A0 A1`, …) → мусор: индекс за пределами блока из 194 глифов;
- строки не ломаются и игра не падает.

Доп. блок (194 глифа 24×24, `work/font_extra.png`): хирагана №0–80, катакана №81–164,
○ △ □ × №166–169, японская пунктуация и скобки №170–193.

Глифы Mac Roman 0x80–0xFF основного шрифта (видимо, для европейских версий) в американском
exe через субтитры **недоступны**.

### Что это значит для кириллицы

| Вариант | Плюсы | Минусы |
|---|---|---|
| **A. Двухбайтовые коды** (`81 xx`), кириллица вместо каны | Без правки кода | Каждая буква = 2 байта: DEMO 110 КБ при месте 68 КБ, VOX 129 КБ при 86 КБ — не влезает |
| **B. Патч процедуры вывода текста** (одиночные 0x82–0xFF → основной шрифт) | cp1251 как задумано, размер текста как у английского | Нужно найти и пропатчить код отрисовки текста (MIPS) |
| C. Кириллица вместо латиницы ASCII | Без правки кода | Не хватает мест (~38 свободных при ~48 нужных), ломает латиницу |

**Рекомендация — B.** Кодировка cp1251 остаётся в силе; 0x80 и 0x81 остаются служебными
(перенос строки и ведущий байт каны/значков кнопок — их можно использовать вместо иконок ПК).

**Вариант B реализован и проверен** — см. `docs/04_exe_patch.md`.

## Перенос М Н О П м н о п (24.10.2026)

Буквы с cp1251-кодами CC–CF и EC–EF портились в резидентном скрипте r_sna (подробно —
`06_gcx.md`). Они перенесены: М 0x90, Н 0x91, О 0x92, П 0x93, м 0x94, н 0x95, о 0x98, п 0x9A
(`encoding_ru.MOVED`). Старые места в шрифте очищены, объём глифов тот же (16 338 из 18 624 Б).
Всё кодирование идёт через `encode()`, поэтому субтитры и GCX переносятся автоматически.
