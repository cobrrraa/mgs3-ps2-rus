# Скрипты уровней (GCX): меню, предметы, подсказки (этап 6)

> Документ написан по ходу работы и сохраняет ход рассуждений. Где план или предположение устарели, ниже стоит блок **«Итог»**. Итоговое состояние перевода — в `README.md`.

## Где текст

- GCX — скрипты уровней в `STAGE.DAT` (156 файлов, по одному на уровень, регион `cache`).
- Строки лежат в «области строк» в конце скрипта и **зашифрованы**; код ссылается на них через
  таблицу (`0x80000000 | смещение` — строка, без флага — блок данных).
- Найдено в памяти по сохранению (`work/ss/vox_ru.p2s`, уровень `v004a`): «I see him!!»,
  «Who's that!», «Speak!» — это строки GCX, не VOX.

## Шифр (из кода игры: 0x124128, ГПСЧ 0x1240F0, вызов 0x1242F0)

```
sec2 = конец заголовка (после 0xFFFFFFFF): u32 size, u32 tab_off, u32 str_off, u32 str_end, u32 seed
байты [sec2+str_off, sec2+str_end) ^= поток:
    state = state * 0x7D2B89DD + 0xCF9 (32 бита); байт = (state >> 15) & 0xFF; state0 = seed
seed = 0 → не зашифровано (игра обнуляет seed после расшифровки)
```

Проверено: расшифрованный `v004a` совпадает с памятью игры байт в байт. Код: `tools/gcx.py`.

## Перевод (`tools/gcx_translate.py` → `work/gcx/gcx_ru.json`)

| Источник | Строк |
|---|---|
| точное совпадение с ПК-русификатором | 888 |
| почти совпадение (отличаются значки кнопок / акценты / приставка PS2) | 171 |
| свой перевод (`work/gcx/gcx_manual.json`) | 129 |
| оставлено по-английски: карта памяти, сеть/DNAS, загрузка камуфляжа, песни, бренды | ~130 |

Значки кнопок ПК (U+E080…) заменяются кодами PS2 из той же позиции английской строки:
`83 02` ○, `83 03` △, `83 04` □, `83 05` ✕, `83 01` отступ, `8C 01`/`8C 02` — глифы страниц (∞ и др.).
Поэтому патч кода изменён: **двухбайтовыми остаются все 0x80–0x8F** (а не только 0x80/0x81),
«…» перенесено с 0x85 на 0x9F (`tools/encoding_ru.py`, `tools/exe_patch.py: LEADS = 0x10`).

## Вставка (`tools/gcx_build.py`, `tools/gcx_apply.py`)

Структура: `[заголовок процедур][sec2: таблица ссылок + строки][байт-код]`. Заголовок ссылается
на байт-код по абсолютным смещениям, поэтому внутри файла ничего не двигается:
- некоторые меню берут только первую строку списка, а следующие ищут сразу за её нулём (вопрос
  «Играете в MGS впервые?», подсказки главного меню). Поэтому строки, идущие подряд, — «цепочка»,
  которая пишется без промежутков;
- цепочка переупаковывается в своих же байтах; если русская длиннее, строки начиная с первой
  не влезшей дописываются (тоже подряд) в конец файла, ссылки `0x80000000|смещение`
  перенаправляются (смещение от начала области строк может выходить за её конец);
- в области строк есть и двоичные данные (двойные нули), их не трогаем — только строки по ссылкам;
- файл хранится расшифрованным с `seed = 0` (игра его не трогает).

Первая версия дополняла короткие строки нулями на месте — в меню пропадали 2-й и 3-й варианты
ответа и подсказки внизу экрана (найдено в PCSX2 24.10.2026).

GCX всегда последний файл своей секции (`cache`), поэтому при росте файла меняются только
размер секции в двух тегах заголовка страницы (заголовок перешифровывается). Сжатая секция должна
влезть в прежний объём: zlib 9, при нехватке — zopfli (на `v004a` выигрыш ~65 КБ при росте 36 КБ).

Проверено на `v004a`, `mk_menu`, `init`: скрипт после перепаковки читается байт в байт.

## Резидентный скрипт r_sna (окна оружия и снаряжения R2/L2)

Найдено при проверке в PCSX2 (24.10.2026), исправлено в тот же день.

1. **Буквы М Н О П м н о п портились** («Листклет с транквилизаткркм»). При загрузке r_sna игра
   обходит его строки по-старому (любой байт ≥ 0x80 — начало пары) и переносит коды страницы
   глифов: если у первого байта пары `b & 0x9F` = 0x8C–0x8F, из него вычитается 4
   (`8C 01` → `88 01`, страница глифов r_sna переезжает из слота 2 в слот 1). Под это правило
   попадают cp1251 CC–CF и EC–EF. Решение без правки кода: эти 8 букв перенесены на свободные коды
   0x90–0x95, 0x98, 0x9A (`tools/encoding_ru.py: MOVED`, шрифт пересобирается).
2. **Мусор вместо описаний** (сигара, прицел, таблетки). r_sna загружается только в пределах
   исходного размера, дописанные в конец строки в память не попадают. `gcx_apply.py` теперь
   отказывается увеличивать r_sna01–03.
3. **Окно — 5 строк и ≈366 px** (по скриншотам: 370 px ещё целиком, 374 px уже переносится посреди слова), длиннее — перенос посреди слова и обрезка.

`tools/gcx_short.py` сокращает тексты r_sna (типовые фразы по правилам, свои короткие версии
в `work/gcx/gcx_short_manual.json`), переносит строки по ширине шрифта, проверяет 5 строк,
бюджет байтов (13 107 из 15 126) и что коды 8C при старом обходе стоят на месте первого байта.
Результат — `work/gcx/gcx_short.json`, применяется поверх `gcx_ru.json`. Отчёт по строкам:
`tools/gcx_resident.py`.

Проверено по памяти после новой игры: в области строк r_sna отличаются от образа только 10 байтов
`8C → 88` (как в оригинале).
